# Beat B0 降维消融：1024 隐藏维度

用户要求接续降维消融，核查旧 A 结构，尝试 Linear 128→512、三视图×4 token 展平为12 token、scene MLP 512→1024→GELU→1024。在 machine1 八张 L4 训练并闭环评测，machine2 的 MBConv 实验独立继续。

## 旧实验核查

旧 A 配置和实际 safetensors 均确认：融合后的 ResNetAdapter 保留两个独立 ResBlock（128通道，stride2）和 AdaptiveAvgPool2d(2,2)；patch_merging.proj.weight 为[256,128]，即 Linear128→256，并未遗漏；scene_adaptor 的两个权重为[512,256]、[512,512]，中间 GELU；state_adaptor 为14→512→GELU→512→GELU→512；t/r输出512，DiT宽512、8层、8heads。VisualEncoder 将[B,3,4,256]变为[B,12,256]，scene MLP后为[B,12,512]，没有把token轴合入通道。

最早的compact256同时采用融合前2×3压缩、128→256→GELU→256、scene identity，因此不属于纯宽度消融；其结果不能归因于宽度本身。之后旧 A 才恢复融合后2×2和scene MLP。旧 A 的0/100不能单独证明512隐藏维度或256投影宽度就是失败原因；本次提高容量是一次检验，不预设成功率。

## 本次路径和控制项

240×320图像按原预处理到256×320，预训练冻结B0输出每视图128×8×10（80token）。以128维进行原多视图融合，随后原两个ResBlock下采样8×10→4×5→2×3、自适应平均池化到2×2，Linear128→512，输出[B,3,4,512]，展平为[B,12,512]。scene MLP为Linear512→1024、GELU、Linear1024→1024。

状态与带噪动作共用原mlp3x_gelu结构，改宽14→1024→GELU→1024→GELU→1024；t/r输出1024；DiT保持8层、每head64维（16heads），每层K/V为[B,16,12,64]；物理动作仍14维。保留tau_token、MeanFlow，未增加共享stage4、MBConv、额外激活或identity替换。新配置直接继承旧 A，只覆写hidden_size、num_heads和视觉输出dim_out以及独立输出路径。无网络源码变更。

共同recipe为beat_block_hammer、50 demos、seed42、200 epochs、globalbatch128、BF16、AdamW1e-4、minmax、horizon24、1state+23actions、5614train/118val样本、8771steps、原decoded-video共享内存缓存、离线BGR→RGB。无需恢复旧完整模型权重，只严格加载同一B0预训练文件。EMA采用已修复BN buffers同步的现有训练代码，该修复不改变main优化过程；此处ResBlock为LayerNorm，无新训练BN。

先配置差异审计和真实数据全模型CPU预检，再八卡两步smoke及main/EMA严格重载；正式训练结束再次严格验证，随后最终main用相同100固定expert-verified seed评测，eager BF16、MeanFlow NFE1、KV开、Graph关、在线RGB不翻转。四分片各25seed，两个独立4卡lane，保留100视频。
